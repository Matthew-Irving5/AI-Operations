# AI Operations integration rules (living architecture checklist)

Read only rows touching the current ticket. The IDs are stable; update a rule when implementation changes, preserving its evidence link. A ticket readback remains required but is not a substitute for these concrete integration conventions.

## Supabase / migrations / privileges

- **DB-01 — Execute as the real caller.** A Supabase `service_role` JWT does **not** grant arbitrary table INSERT/SELECT when explicit Postgres grants deny it. For prompt candidate creation, call the existing restricted `create_prompt_candidate` SECURITY DEFINER RPC; do not insert into `prompt_versions` directly or weaken its ACL. Extend existing RPCs and caller-role tests, not service privileges. (AI-16 PR #170, commit `170d537d`)
- **DB-02 — Protected observability tables are not a diagnostic API.** Direct PostgREST `service_role` SELECT on protected `trace_events` / `prompt_version_transitions` is intentionally denied (403/42501). Read via the authorized UI/query RPC; never add SELECT grants solely to debug. (AI-16/19 staging 15/20 Oct)
- **DB-03 — Shared migrations are one timeline.** Before creating migrations in a parallel worktree, inspect committed migrations on main AND active sibling PRs. Use a fresh unique version prefix; do not reuse `20261015210000`. Forward migrations only; never rewrite applied history. Resolve collisions before composing/deploying sibling PRs. (AI-16 `cde425bd`, AI-19 `5209bd10`)
- **DB-04 — Generated type parity is semantic and follows the migrated schema.** Use the exact Supabase CLI version pinned in `pnpm-lock.yaml`; if the installed CLI differs, run `corepack pnpm install --frozen-lockfile` first. Schema drift checks must distinguish actual missing/changed columns/RPC signatures from CLI representation changes such as an inline `SetofOptions` row versus a referenced row array. After applying the full migration chain locally, run `corepack pnpm environment:drift -- repo-local`; when the difference is real, regenerate and commit `packages/db/src/database.types.ts` with the schema change. Do not hand-edit stored generated types to conceal real drift. (AI-19 staging run `39475753561`; AI-17 local migration proof)
- **DB-05 — Validate at every writing boundary.** Existing SQL write/commit procedures can enforce narrower rules than TypeScript or Edge validation. When adding a provider shape, inspect SQL validations and persisted schemas as well. Example: `commit_instrumented_ai_report` formerly demanded at least one report section while the governed provider schema allowed zero. (AI-16 `39e68b5`, `cde425b`)
- **DB-09 — Reconcile the provider's full actual cost.** Keep the reservation amount as the held estimate, record actual provider consumption even when it exceeds that estimate, and release only the unused remainder. Update the relevant hard-cap total atomically with settlement; never clamp actual cost to the estimate or reject reconciliation after the provider has charged. (AI-20 PR evidence pending)
- **DB-12 — Keep per-call pricing and complete usage together.** Capture the immutable effective `model_pricing.id` during reservation; calculate the later provider actual against that exact row, including cache-write tokens. Reject incomplete or stale/unverified usage for reconciliation and record the failure for operator review; never silently use the latest price or treat a missing usage field as zero. Prove the reservation→webhook→settlement path and immutable-row ACL/trigger in local DB tests. (AI-20 PR #178; local reset and pgTAP)
- **DB-13 — Async terminal transitions must accept completion from a wait state.** When a canonical request can wait for delegated or external work, verify every successful and unsuccessful terminal result can transition from that wait state when the reply returns. Add a database regression against the actual transition trigger so an omitted async edge cannot strand completed work. (AI-17 migration `20261021155523`; `ai17_inter_agent_transitions.sql`)
- **DB-14 — Preserve full routine behavior when extending SQL integration boundaries.** `CREATE OR REPLACE FUNCTION` must retain the prior writes, validation, audit context, authorization, `SECURITY DEFINER` or `SECURITY INVOKER` mode, and pinned `search_path` unless a contract explicitly changes them. Compare with the previous migration and keep regression assertions for both old and new behavior. (AI-17 `record_conversation_handoff_event()` regression)

## Edge / runtime / package boundaries

- **EDGE-01 — Deployment import maps differ from shared typecheck.** A shared `supabase/functions/deno.json` used in local `deno check` does not automatically configure each deployed Edge Function. Register the affected function's `import_map` in `supabase/config.toml` (such as `feedback-submit`) when using `@ai-operations/*` aliases; prefer the repo's established per-function mapping. (AI-19 `ff1ee65b`, staging `39473033548`)
- **EDGE-02 — Keep workspace sources in QA staging.** Imports added across packages must be included in the existing `infrastructure/scripts/qa-workspace-dependencies.ts` staging of local test sources. A missing new package source can break Chromium test boot even when Edge typecheck passes. (AI-19 `ddf83218`, CI `38778271919`)
- **EDGE-03 — Adapt Supabase RPC builders to Promise-based ports.** Supabase JS `.rpc()` returns a thenable `PostgrestFilterBuilder`, not a native `Promise`; when an Edge adapter port requires `Promise`, wrap the call in an `async` function and `await` it. Run `deno check` on deployed function entrypoints as well as handler tests. (AI-17 Edge adapter typecheck)
- **RUNTIME-01 — Cloudflare is not Next dev.** Relevant Worker routes must use the established OpenNext/Wrangler production-like preview when modified. Do not assume Next dev cookie/redirect/middleware behaviour is identical. Public origin must remain the browser's origin, not an internal `localhost` host. If auth isn't touched, do **not** introduce broad local MFA setup. (AI-16 `f9e40378`, `36fdcffc`)
- **RUNTIME-02 — Match toolchain and runtime settings.** Invoke repository-pinned `corepack pnpm` (10.18.2 at incident time), not global pnpm 11; align local WSL/CI Node, generated OpenNext manifests and Worker build-vs-runtime variables. Prefer isolated targeted reproduction over committing CI-only guesses. (AI-16 `de04d023`, `aed1f0de`)
- **RUNTIME-03 — Parse actual CLI output, not guessed JSON substrings.** Supabase metadata CLI output may contain warnings/other JSON. Use stable machine-readable modes and a robust defined parse contract; test the Linux CI stdout shape. (AI-19 `f1ba2852` through `62ce7845`)

## Provider / orchestration / acceptance contracts

- **GITHUB-01 — Validate both requested and credential owners.** A fixed allowlisted repository URL does not prove that the caller-supplied target or configured token identity is approved. Reject injected owner aliases before rate-limit/MFA and GitHub work; verify the authenticated token with GitHub `/user`; only then construct repository URLs from the exact `Matthew-Irving5` owner. Treat `BrightSG` as a case-insensitive hard deny, audit only safe reason codes, and prove denied identities make zero repository calls. (AI-35 Career boundary regression)
- **GITHUB-02 — Preserve owner denials across authenticated proxies.** A web proxy may validate and forward only the documented owner-target shapes to the authenticated Edge parser so it can emit the safe denial audit before MFA/provider work; do not short-circuit those known denials at the proxy. Keep unknown fields rejected at the proxy and retain Edge validation as authoritative. (AI-35 staging run `39639201782`, follow-up on `3835c62`)
- **AI-01 — One provider-output contract, end to end.** Compare the _persisted_ JSON schema sent to Responses with the shared runtime validator, SQL commit constraints and fixtures. All allowed shapes must succeed end-to-end: `report_sections: []` and permitted ASCII section codes with uppercase letters must be canonicalised as designed. Reject truly disallowed input; never fabricate sections to silence errors. (AI-16 `39e68b5`, `cde425b`, AI-19 `eaee6c7f`)
- **AI-02 — Candidate and rollback are different valid request variants.** Build API request validators from existing model/budget policies and the actual rollback journey. The Systems weekly launch allows the specifically authorised Luna/$0.05 and Terra/$0.15 combinations (no search), not an accidental cross-pair; keep route/harness/SQL budget semantics aligned. (AI-19 `de0caeaf`)
- **COST-01 — Delegated runs inherit the initiating cost root.** Keep AI call and reservation rows attributed to the specialist `run_id`, but stamp each delegated `workflow_runs.cost_root_run_id` from `coalesce(source.cost_root_run_id, source.id)` inside the atomic delegation RPC. Reservation and settlement must resolve the on-demand budget through `coalesce(cost_root_run_id, run_id)`; delegated runs never get a fresh independent hard cap. (AI-20 PR #178, AI-17 delegation contract)
- **ACC-01 — Acceptance proof is an interface.** Before staging, inspect suite/profile selector, browser-session reuse, artifact writer, strict validator and consumer. An `auth-browser` artifact and a targeted `promptGovernanceProof` cannot be silently interchanged or written to the same incompatible output. Use the established exact-head/lease mechanism; no ad hoc ephemeral helper stored under ignored test-results. (AI-16/19 `cbe549bb`, `777184d1`)
- **ACC-02 — Human MFA is a genuine external gate.** Do not wait 300 seconds for sign-in before confirming the operator sees the current headed browser. Pause and ask for the action clearly; reuse the accepted auth context where possible. Skip complete local MFA for unaffected tickets. (AI-16/19 15/20 Oct)
- **ACC-03 — Authenticated shell journeys require hosted browser acceptance.** Candidate profile selection must account for the protected app shell and its authenticated platform journey, even when no auth endpoint changes. Changes to the shell layout/navigation or `tests/e2e/platform-authenticated.spec.ts` require the `auth-browser` profile; do not auto-accept a deployment-only smoke as a user-journey proof. (AI-22 PR #174, staging run `39614521311`)
- **OPS-01 — The failure message should give the cause, not just the stage.** Return the failed invariant, owning boundary/contract, expected versus actual and precise safe field/path. Never log passwords, PII, raw provider prompts or restricted trace tables to achieve diagnostic accuracy. (AI-16/19 staging investigations)
