# SECURITY DEFINER RPC execution matrix

All current `public` SECURITY DEFINER functions are classified below. The
forward migration revokes `EXECUTE` from `PUBLIC`, `anon`, `authenticated`, and
`service_role` before restoring only these principal grants. The pgTAP check
compares the database catalog against this matrix, including newly added
functions, so an unclassified definer cannot silently become an API.

## Intentionally not callable through the Data API

These SECURITY DEFINER functions have no `EXECUTE` grant to API roles. They
are obsolete, local-test-only, called only inside another definer function, or
trigger functions that PostgreSQL invokes through their trigger—not RPCs:

- `reserve_recurring_budget(uuid,uuid,numeric)`
- `calculate_spend_forecast(uuid,date)`
- `record_provider_usage_reconciliation(uuid,timestamptz,timestamptz,numeric,text)`
- `add_model_pricing(uuid,uuid,timestamptz,numeric,numeric,numeric,text)`
- `adapt_mobile_record_v1(uuid)`
- `record_mobile_source_freshness()`
- `record_legacy_apple_bridge_freshness()`

The test matrix requires every current public SECURITY DEFINER function to be
classified. Adding another one requires an explicit caller decision and
regression update before the migration is accepted.
